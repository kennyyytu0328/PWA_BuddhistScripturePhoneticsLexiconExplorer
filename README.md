# SutraFlow PWA · 心經逐字解讀沉浸器

An offline-first mobile PWA for reading the *Heart Sutra* (《般若波羅蜜多心經》, Xuanzang's translation, common recitation text with mantra) word by word, the way it is printed in a sutra book: vertical text, right to left, page by page.

Tap a term to open its entry from Ding Fubao's *Dictionary of Buddhist Studies* (丁福保《佛學大辭典》), quoted verbatim. Switch the reading aid above each character between Zhuyin, Pinyin, Sanskrit (IAST) and none.

## Features

- **Zen Mode reader**: full screen, dark, no navigation bars. The screen stays on while you read (Wake Lock).
- **Accordion-book layout**: `writing-mode: vertical-rl`, swipe horizontally right to left, pages snap into place. The first page is a cover with the sutra title and translator; on first open it nudges once to show that the book swipes.
- **Lexicon drawer**: tap a term, feel a short vibration, and a bottom sheet shows the reading, the DFB definition, cross-references (見X條 / 與X同) and the source attribution.
- **Phonetic toggle**: Zhuyin → Pinyin → IAST → none, rendered with `<ruby>`. Your choice and reading position are saved on the device.
- **Plain-language notes**: each passage has a project-written vernacular rendering, kept visually separate from the dictionary text and labelled 「白話參考」.
- **Installable and 100% offline**: the sutra, the dictionary subset and the font subsets are precached on install. Nothing is loaded from a third-party server.

## Content principles

- **Definitions come only from the DFB source text.** They are shown word for word; nothing is rewritten, summarised or generated by a model.
- **Readings follow Taiwanese usage.** Pinyin is generated with `pinyin-pro` (citation tones, no tone sandhi), then overridden where Buddhist or Taiwanese readings differ (般若 bō rě, 識 shì …). The whole-sutra result is locked in `data/readings.lock.json` and was checked against the Ministry of Education dictionary.
- **The text is collated** against CBETA T08n0251. The build fails if the tokens do not reproduce the CBETA text exactly.
- **Human review is required to ship.** `data/heart-sutra.json` and `data/iast.json` carry review flags; a production build refuses to run while any of them is `false`. Review notes are in [`review/`](review/).

React 19 · TypeScript · Vite · Tailwind CSS · `vaul` (bottom sheet) · `vite-plugin-pwa` (Workbox) · Dexie.js · `pinyin-pro` · Vitest · Playwright

## Getting started

Requirements: Node.js 20.19+ or 22.12+, and pnpm 10.

```bash
pnpm install
```

### CBETA source text (required for builds)

The build compares the sutra against the CBETA edition, which is **not included in this repository**. Before building, save a local copy as UTF-8 plain text at:

```
data-sources/cbeta/T08n0251.txt
```

Get the text from <https://cbdata.dila.edu.tw/stable/juans?work=T0251&juan=1>. Lines starting with `#` are ignored and punctuation is stripped before comparison. See [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) for details.

### Scripts

| Command | What it does |
|---|---|
| `pnpm build:data` | Builds `public/data/` (sutra with phonetics, DFB subset, gaiji images) and runs all data checks. Unreviewed data only warns. |
| `pnpm build:fonts` | Subsets Noto Serif TC and Noto Sans TC to the characters the app uses. |
| `pnpm build:icons` | Generates the app icons and favicon. |
| `pnpm dev` | Starts the Vite dev server (run the three build steps above first). |
| `pnpm build` | Production build: checks review flags, runs all build steps, type-checks and bundles to `dist/`. |
| `pnpm preview` | Serves `dist/` locally. |
| `pnpm test` | Unit and data acceptance tests (Vitest). |
| `pnpm exec playwright test` | End-to-end tests against the production build on a Pixel 7 profile, including offline tests. Run `pnpm build` first. |
| `pnpm lint` | Lints with oxlint. |

First Playwright run: `pnpm exec playwright install chromium`.

## Deploy (GitHub Pages)

Every push to `main` runs [`.github/workflows/deploy-pages.yml`](.github/workflows/deploy-pages.yml): it installs, runs `pnpm test`, builds with `BASE_PATH=/<repo>/` and publishes `dist/` to GitHub Pages.

One-time setup:

1. **Settings → Pages → Build and deployment → Source: GitHub Actions.**
2. Store the CBETA text as a repository secret, base64-encoded:

   ```bash
   base64 -w0 data-sources/cbeta/T08n0251.txt | gh secret set CBETA_T08N0251_B64
   ```

To try a subpath build locally: `BASE_PATH=/<repo>/ pnpm build && BASE_PATH=/<repo>/ pnpm preview`. In Git Bash, prefix with `MSYS_NO_PATHCONV=1` so the path is not rewritten.

## Project layout

```
data/                 Hand-edited source data: sutra tokens, reading lock, IAST table
data-sources/dfb/     DFB TEI P5 source (31,366 entries) and gaiji images
data-sources/cbeta/   Local CBETA text (gitignored, build-time only)
scripts/              Data, font and icon build scripts
src/components/       Reader, cover, tokens, lexicon drawer, phonetic toggle
src/hooks/            useWakeLock, useHaptics, usePhoneticMode, useReadingProgress …
src/lib/              Data loading, Dexie store, ruby layout
tests/acceptance/     Acceptance tests for the data, reader and PWA units
docs/spec/            Requirements and design decisions per unit
review/               Reading, IAST, editorial and manual device review records
```

`data/heart-sutra.json` is the single source of truth for the text. Its token strings, joined together, must match the sutra exactly; `lex` points to a DFB headword and `py` overrides a reading. The format is documented in [CLAUDE.md](CLAUDE.md) §3.3.

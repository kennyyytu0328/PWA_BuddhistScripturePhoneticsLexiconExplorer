# 原音隨誦（聲）設計

2026-11-18。使用者選定：速度鍵加第四段「聲」（方案 A）；封面先唸經題再翻頁。

## 目的

學讀音時，讀者想**聽到**每個字怎麼唸，同時看到光標停在正在唸的字上。平常默誦仍用無聲的計時光標，不要每次都放錄音。

## 目標／非目標／反目標

- 目標：選「聲」後按「誦」播放全經錄音，光標逐字跟著聲音走；暫停、續誦、翻頁、寬頁跟隨、進度線、誦畢的行為與計時模式一致；離線可用。
- 非目標（首版不做）：調整錄音速度（`playbackRate`）、點字聽單字、多種聲音、逐句重播、咒語重複。
- 反目標：預設就播放錄音；新增控制鍵或改動底部版面；`requestAnimationFrame` 連續迴圈（沿用 2026-11-17 隨誦設計的反目標）；釋出未確認授權的錄音。

## 現況

- 「誦」由 `useFollowAlong`（`src/hooks/useFollowAlong.ts`）以每字一個 `setTimeout` 推進光標；速度鍵 `follow-pace` 輪替 中 → 快 → 慢（225／300／150），存在 Dexie `prefs` 的 `followPace`（字串）。
- 光標驅動：`data-follow` 配色、琥珀線、進度線（REQ-RDR-036）、自動翻頁與寬頁跟隨（REQ-RDR-034，含 Q-RDR-054）、暫停條件（REQ-RDR-035）、誦畢（REQ-RDR-037）。
- 錄音：`sutra_speech.mp3`（使用者以 luvvoice.com 產生；90.26 秒，24 kHz 單聲道 48 kbps，約 530 KB，無 ID3）；字幕 `sutra_speech.mp3.srt`（54 條，簡體、多處同音錯字）。使用者已試聽：讀音正確（含 般若 bō rě 與咒語）。
- SRT 對位（已核對）：第 1 條為經題（0–2.32 s）；第 2–49 條與經文以標點切分的 48 句一一對應、字數完全相同（到「即說咒曰」82.18 s）；第 50–54 條（咒語 83.56 s 起）切在句中、共 17 字，對不上經文 4 句 18 字。
- Service worker 只預快取 `heart-sutra.ast.json`、`lexicon.dfb.json`、`data/gaiji/*.png`；`data/` 下其他檔走第三層 SWR（REQ-PWA-008）。

## 行為（使用者已決定）

1. 速度鍵輪替 中 → 快 → 慢 → **聲** → 中；選擇照舊存 Dexie，重開仍是「聲」。
2. 「聲」時按「誦」播放錄音，光標隨聲音逐字前進；配色、琥珀線、進度線、自動翻頁、寬頁跟隨與計時模式相同。
3. 現有暫停條件（停、開名相、開白話參考、滑到別頁並停靠、App 進背景）同時暫停錄音；按「誦」續誦規則不變：所見頁為光標頁 → 從光標字續播；所見為其他經文頁 → 從該頁第一字開始。
4. 錄音唸完「訶」即誦畢，行為同 REQ-RDR-037。
5. 在封面按「誦」（「聲」模式）：停在封面，播放經題（0–2.32 s），經題不標光標；經文第一字開始時翻到 s1。
6. 錄音隨 App 預快取，離線可用。

## 我的判斷（2026-11-18 使用者確認全部採用）

1. **計時模式之間的切換照舊**（播放中改速度自下一字生效，REQ-RDR-032）；**進出「聲」時暫停**並保留光標，下次按「誦」以新模式從光標續誦。理由：計時與錄音是不同時間軸，無法無縫接續。
2. **速度鍵字樣**「聲」；`aria-label`「隨誦速度：原音朗讀」。Dexie 值 `"voice"`。理由：沿用單字圓鈕，`followPace` 原本就是字串。
3. **經題期間**：按鈕顯示「停」；不顯示進度線、不標 `data-follow`；經文第一字開始時才出現。期間按「停」再按「誦」從經題開頭重播。
4. **續播定位**：續誦時把錄音移到光標字的起始時間。
5. **錄音無法播放**（載入失敗、`play()` 被拒）：停止並保留光標，與按「停」相同，不另顯示錯誤。理由：已預快取，極少發生；不新增 UI。
6. **光標推進方式**：每字以 `setTimeout` 排到下一字起始時間，每次依 `audio.currentTime` 重新校正；不用 `requestAnimationFrame`、不靠 `timeupdate`（約 4 Hz，粗於一字 0.3 s）。
7. **檔案配置**：
   - 原始檔：`data-sources/voice/sutra_speech.mp3`、`.srt`。
   - 時間碼：`data/voice-timings.json`，由一次性腳本 `scripts/build-voice.ts`（`pnpm build:voice`）從 SRT 與錄音產生、人工試聽後提交，屬已審閱資料（同 `readings.lock.json` 的定位）；格式：`{ audio, duration, title: {start, end}, chars: [start₀ … start₂₅₉] }`（秒）。
   - 驗證與發佈（實作計畫確認時改為另立 `pnpm build:voice`，`pnpm build` 串接之，`build:data` 與 `check-review.ts` 不動；Q-DAT-023）：`pnpm build:voice` 驗證：260 筆、嚴格遞增、皆在 `title.end` 與 `duration` 之間、`audio` 檔存在；任一失敗即中止。複製錄音到 `public/data/voice.mp3`（不改內容）。
   - Service worker 預快取 `data/voice.mp3` 與時間碼（第二層，REQ-PWA-007 擴充）。
8. **句內分配**：每條 SRT 的區段內，以錄音能量找出發聲結束點，把該句各字平均分配在「句首 → 發聲結束」之間。咒語段（83.56 s 起）以能量找出 3 處停頓切成 4 句再同樣分配；停頓不是 3 處、或位置不落在經文的逗號，改用 `build:voice` 的手動覆寫：咒語 18 字的起始時間依錄音能量的音節起點人工填入，驗證規則同其他字。
9. **試聽審閱**：`voice-timings.json` 帶 `review.voice` 旗標；`pnpm build:voice` 為 false 時只警告，正式 `pnpm build`（`build:voice --release`）則中止，同讀音審閱的做法。使用者以「聲」模式全經試聽、確認光標對位後改為 true，紀錄寫在 `review/voice-review.md`。

## 規格與測試（spec-flow 維護模式）

- reader 單元：新增 Q-RDR-055（本設計決議）；修改 REQ-RDR-032（第四段「聲」）、REQ-RDR-035（「聲」模式封面行為）；新增 REQ 涵蓋原音隨誦（時間對位、暫停續播、誦畢、播放失敗）。
- pwa 單元：REQ-PWA-007 加入錄音與時間碼預快取。
- data 單元：`build:data` 對時間碼的驗證。
- 驗收測試以假的 `HTMLMediaElement` 時間（依測試時鐘前進）驗證光標對位，不依賴真實音訊輸出；另加一個真實播放的冒煙測試（錄音可載入、`play()` 成功）。
